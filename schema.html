Trace 06 · The schema

The rules live in the tables, not in the code.

Twenty production tables, one sequence, and a wall of constraints. This is the DBMS coursework made physical: every business rule that must never be broken is declared in DDL, so the database refuses bad data even if a bug slips through the application.

The territory, in five domains

DomainTablesWhat they hold
IdentityUNIVERSITY, RESEARCHER_PROFILE, USER_SESSIONWho exists, where they belong, who is logged in
ExpertiseRESEARCH_AREA, RESEARCHER_AREA, SKILL, RESEARCHER_SKILLAreas and skills, linked to researchers with levels
PublicationsPUBLICATION, PUBLICATION_AUTHOR, PUBLICATION_AREA, CITATION_RECORD, EXTERNAL_PUBLICATION_SOURCEPapers, ordered author lists, citation snapshots, import provenance
CollaborationCONNECTION, RESEARCH_POST, POST_REQUIRED_AREA, POST_REQUIRED_SKILL, RESEARCH_APPLICATION, APPLICATION_PUBLICATION, NOTIFICATIONPosts, applications, connections, notifications
OversightAUDIT_LOG (+ enhanced-ER tables from Trace 07)Who did what, and the student/faculty specialization

Notice the naming pattern of the middle two domains: X, Y, and X_Y. A standalone noun gets its own table; a relationship between two nouns gets a junction table named after both.

Reading a table definition

The profile table is the heart of the system. Read its DDL the way you would read a class declaration: columns are fields, constraints are invariants:

Constraint by constraint, this is what the database enforces for free:

ConstraintKindWhat it guarantees
researcher_id ... PRIMARY KEYPKEvery profile has exactly one unique identity: the value comes from RCP_ID_SEQ (Trace 05)
NOT NULL columnsrequired fieldNo profile without email, hash, role, name: the INSERT is rejected, the app cannot forget
DEFAULT 'ACTIVE'defaultOmitting the column still yields a sane value
fk_rp_universityFKuniversity_id must point at a real university row, or be NULL (independent researcher). Orphan references are impossible
ck_rp_roleCHECKrole is one of four values: an enum enforced by the engine
ck_rp_orcidCHECK + regexAn ORCID, when present, must match the official 0000-0000-0000-000X shape

In Java terms

A CHECK constraint is an if you write once and the database runs on every INSERT and UPDATE forever. The difference from application validation: app validation can be bypassed by a bug or a second client; the constraint cannot. RCP does both: validate in src/server for good error messages, constrain in DDL for truth.

Sessions are rows too

Logging in does not create magic server state: it inserts a row. The session table is how "who is logged in" survives restarts and scales across instances:

Note what is stored: token_hash, not the token. The browser holds the real token in a cookie; the database keeps only its SHA-256 digest. If the database is ever read by an attacker, sessions cannot be hijacked from it. Trace 08 follows the token through login and logout: logout is just UPDATE ... SET revoked_at on the row you are looking at.

Many-to-many, the junction pattern

A researcher has many areas; an area belongs to many researchers. Relational databases model that with a third table whose primary key is both foreign keys together:

  • The composite primary key (researcher_id, area_id) makes duplicates impossible: one link per pair, enforced by the engine.
  • The junction table carries attributes of the relationship itself: expertise level, years, whether this is the researcher's primary area. That is why it is a real table and not just a link.
  • The same pattern repeats for RESEARCHER_SKILL, PUBLICATION_AUTHOR (with author order), POST_REQUIRED_AREA (with weight), and four more junctions.

In Java terms

An ER diagram's M:N relationship becomes a class whose fields are two references plus the relationship's own data: class ResearcherArea { Researcher researcher; Area area; int expertiseLevel; }: with a uniqueness constraint on the pair of references.

Normalization, as practiced

The schema is normalized on purpose, and the payoff is visible in the data: university names exist once in UNIVERSITY and are referenced by ID everywhere, so renaming a university is one UPDATE instead of thousands. Research areas are a controlled vocabulary (RESEARCH_AREA) rather than free text, which is what makes faceted search and matching possible later. The cost: more JOINs: is paid in the views you meet in the next trace.

Breakpoint: the scripts run in order

database/ is numbered for a reason: 00_reset drops everything, 01_schema creates tables, 02_seed_data fills them, 03 adds views and PL/SQL, 04 grants privileges to the runtime user, 05 tests the result. Each file assumes the previous ones ran: exactly like numbered migration scripts.
