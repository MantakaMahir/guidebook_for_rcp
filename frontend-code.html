APPENDIX A / frontend code

Appendix A · Frontend code

Every React page, explained from URL to API call.

This page is the frontend reading guide. It does not paste every source file again; the canonical code remains in the RCP repository. Instead, it explains every frontend file by role, shows the important code shapes, and names the backend or database path each screen depends on. Blocks labeled as teaching sketches are shortened on purpose.

The frontend rule

In this Next.js app, most page files are server components. They run on the Node server, fetch data before HTML is sent, and return JSX. Files that start with 'use client' run in the browser and are used only where the user must type, click, submit, or refresh the current route.

Frontend boundary

React components render UI. They do not open Oracle connections. Server pages may call src/server/* helpers because they run on Node; client components must call /api/* routes with fetch().

Global shell code

The layout wraps every route. SessionActions() is async because it checks the session cookie on the server before rendering the header. That is why logged-out users see sign-in links and logged-in users see their workspace link without an extra browser request.

Client mutation shape

This is the pattern used by the frontend forms: stop the default browser submit, serialize the form, send JSON to an API route, handle the response, then redirect or refresh the current server-rendered route.

Frontend request patterns

PatternWhere usedWhy it exists
Server page readsDirectories, details, dashboard pages.Faster first paint and no duplicate browser API fetch for initial data.
Client form mutationsAuth, profile, editors, workflow buttons.The browser owns form state and submits JSON to protected API routes.
GET query filtersResearcher/publication/opportunity search pages.Filters become shareable URLs and server pages can read searchParams.
router.refresh()Editors and action buttons after success.Re-runs the server page so fresh database state appears without hand-maintained client cache.
notFound()Dynamic profile/publication/post routes.One simple way to hide missing, private, inactive, or unauthorized records.
