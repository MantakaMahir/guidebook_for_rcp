Appendix C · SQL ↔ code map

How SQL is connected to frontend and backend code.

This is the wiring page. Start with a screen, follow it to an API route or server page, then to a backend helper, then to the Oracle objects that helper reads or writes. It also explains where DDL, DML, views, packages, triggers, grants, and tests fit into the running website.

The full path

  • BROWSERReact UI

    A page renders data or a client form submits JSON.

  • NEXT ROUTEPage or API file

    Server pages call helpers directly; client forms call /api/*.

  • SERVER HELPERsrc/server/*.ts

    Validates input, checks ownership, starts transactions, and binds SQL values.

  • ORACLETables, views, packages, triggers

    Stores rows, enforces constraints, runs trigger/package logic, and returns result sets.

How to trace any new feature

  1. Find the screen file in src/app/**/page.tsx or the client component with the button/form.
  2. If it is a read-only server page, follow its imported src/server/* helper.
  3. If it is a client mutation, follow its fetch('/api/...') call to src/app/api/**/route.ts.
  4. From the route, follow the imported helper in src/server/*.ts.
  5. Inside the helper, read the SQL text and binds; map each table/view/package to the schema, PL/SQL, and SQL-type sections.
  6. Check 06_enhanced_er_migration.sql for triggers that run automatically after the helper writes rows.
  7. Check 04_security.sql to confirm the runtime user is allowed to perform that SQL.
