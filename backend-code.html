APPENDIX B / backend code

Appendix B · Backend code

Every API route and server helper, explained.

This page is the backend reading guide. It follows a request through API route files, security checks, validation, service helpers, transactions, and database writes. Use it with Appendix C when you want the exact SQL objects behind each helper. Blocks labeled as teaching sketches are shortened on purpose.

The backend rule

Backend code lives in two places: src/app/api/**/route.ts receives HTTP requests, and src/server/*.ts owns business logic and database access. Route files should stay thin; server helpers do the real work.

Backend boundary

Only backend/server code imports oracledb, reads environment variables, hashes passwords, creates cookies, or executes SQL. Client components call the backend through HTTP.

Oracle connection helper

query() is for reads. withTransaction() is for mutations that must commit together or roll back together. This is the Node equivalent of a JDBC helper around DataSource, PreparedStatement, commit(), and rollback().

Auth helper shape

Registration validates untrusted input, hashes the password, creates a random session token, stores only the token hash in Oracle, and returns the raw token only once so the route can set the cookie.

Backend safety checklist

Safety pointWhere implementedWhy it matters
Untrusted input validationRoute files plus server helper validation.Rejects bad data before it reaches business logic or SQL constraints.
Oracle named bindsAll runtime SQL helpers.Prevents SQL injection for values.
Sort allow-listssearch.ts.Identifiers cannot be bind values, so accepted sort names are enumerated.
TransactionswithTransaction().Parent/child writes commit together or rollback together.
Row locksSELECT ... FOR UPDATE in workflow helpers.Prevents concurrent requests from racing a status change.
Least privilegedatabase/04_security.sql.The runtime user can run the app, not rebuild the schema.
